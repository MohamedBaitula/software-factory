# Quality Rules

Use this file to define what "good enough to review" means for this project.

## Expectations

- Keep changes easy to review.
- Cover risky behavior with tests.
- Preserve existing behavior unless the goal says otherwise.
- Leave clear notes when validation cannot be completed.

## Stop Conditions

Pause for human review if the work requires secrets, paid services, destructive
data changes, production deployment changes, or ambiguous product decisions.
